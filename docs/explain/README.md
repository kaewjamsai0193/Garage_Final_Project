# คำอธิบายโค้ด

ไฟล์ในโฟลเดอร์นี้อธิบายว่าโค้ดแต่ละส่วนทำอะไร ทำไมเขียนแบบนั้น และคำถามที่มักถูกถามกับจุดนั้น
หนึ่งไฟล์ต่อหนึ่ง task ตามแผนใน `docs/superpowers/plans/`

| ไฟล์ | เนื้อหา |
|---|---|
| `task-01-scaffold-and-config.md` | โครงโปรเจกต์ การอ่านค่าตั้ง การเชื่อมฐานข้อมูล และวิธีตรวจงานของโปรเจกต์นี้ |
| `task-02-users-table-and-migrations.md` | ตาราง users, Alembic migration, constraint ในฐานข้อมูล และโครงเทสต์ที่เตรียมไว้ |

## วิธีตรวจงานของโปรเจกต์นี้

**เฟส 1-2 ตรวจด้วยมือ** ผ่าน Swagger ที่ `http://localhost:8000/docs` ผ่านหน้าเว็บ และผ่าน psql
เพราะสิ่งที่สองเฟสนี้สร้างคือล็อกอิน หน้าจอ และตารางข้อมูล ซึ่งเปิดดูแล้วรู้ทันทีว่าถูกหรือผิด
รายการตรวจของแต่ละ task อยู่ในแผนของเฟสนั้น

**เฟส 3-5 จะเขียนเทสต์อัตโนมัติเฉพาะสามเรื่อง**

| เรื่อง | ทำไมตาไม่เห็น |
|---|---|
| ตัดสต็อกแบบ FIFO | หน้าจอขึ้นว่าสำเร็จเหมือนกันหมด ไม่ว่าจะตัดจาก Lot ถูกหรือผิดใบ |
| ปัดเศษ VAT | ยอดรวมดูปกติทุกกรณี ต้องบวกทีละบรรทัดเทียบเองถึงจะเห็นว่าเศษหาย |
| จองเลขที่เอกสาร | เลขข้ามเห็นก็ต่อเมื่อไล่เรียงทั้งเดือน และเกิดเฉพาะตอนบันทึกไม่สำเร็จซึ่งจำลองด้วยมือยาก |

หลักที่ใช้ตัดสินคือ **ถ้าเปิดดูแล้วรู้ว่าผิด ให้เปิดดู ถ้าเปิดดูแล้วไม่รู้ ต้องเขียนเทสต์**

ทั้งสามเรื่องคือจุดที่ตัวเลขเงินผิดได้โดยไม่มีใครรู้ ซึ่งเป็นจุดขายหลักของระบบตาม
`new_scenario_summary.md` ที่ว่าระบบนี้บอกกำไรจริงไม่ใช่แค่ยอดขาย

## เอกสารอ้างอิงอื่น
