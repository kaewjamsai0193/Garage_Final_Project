# Task 1 — โครงโปรเจกต์ ค่าตั้ง และการเชื่อมฐานข้อมูล

**ไฟล์ที่เกิดขึ้น** `.gitignore`, `backend/requirements.txt`, `backend/.env`, `backend/.env.example`, `backend/app/config.py`, `backend/app/db.py`, `backend/app/main.py`, `backend/tests/test_health.py`

**ผลลัพธ์** แอปบูตได้ ต่อ PostgreSQL ได้จริง และมีเทสต์ตัวแรกที่ผ่าน

## 1. โครงโฟลเดอร์ ทำไมแบ่งแบบนี้

```
backend/app/
  config.py      อ่านค่าตั้งจาก .env ที่เดียว
  db.py          engine และ session factory
  main.py        ประกอบแอป
  models/        ตารางในฐานข้อมูล
  schemas/       รูปแบบข้อมูลเข้าออกของ API
  core/          ของกลางที่ทุก endpoint ใช้ร่วมกัน
  api/           endpoint แยกตามกลุ่มงาน
```

ระบบนี้จะมีตารางประมาณ 24 ตารางและหน้าจอ 18 หน้า ถ้าเขียนรวมไฟล์เดียวจะแก้ไม่ไหวตั้งแต่เฟส 3
การแบ่งนี้ทำให้ตอบได้ว่า "โค้ดส่วนไหนอยู่ที่ไหน" โดยไม่ต้องไล่หา

`models` กับ `schemas` ต่างกันตรงที่ `models` คือหน้าตาของข้อมูล **ในฐานข้อมูล** ส่วน `schemas` คือหน้าตาของข้อมูล **ที่วิ่งเข้าออก API** สองอย่างนี้ไม่เท่ากันเสมอ เช่นตาราง `users` มีคอลัมน์ `password_hash`
แต่ schema ที่ส่งออกไปให้ frontend ต้องไม่มีคอลัมน์นั้น

ทุกโฟลเดอร์มีไฟล์ `__init__.py` เปล่า ๆ เพื่อบอก Python ว่านี่คือแพ็กเกจ ไม่ใช่โฟลเดอร์ธรรมดา
`tests/__init__.py` ยังมีผลข้างเคียงที่จำเป็นด้วย คือทำให้ pytest ใส่โฟลเดอร์ `backend/` เข้าไปใน
path การค้นหาโมดูล เทสต์จึง `import app.main` ได้โดยไม่ต้องตั้งค่าอะไรเพิ่ม

## 2. `requirements.txt` ทำไม pin ทุกเวอร์ชัน

```
fastapi==0.115.6
sqlalchemy==2.0.36
...
anyio==4.9.0
```

`==` คือระบุเวอร์ชันตายตัว ไม่ใช่ `>=` ที่แปลว่า "เอาตัวใหม่กว่านี้ก็ได้"

เหตุผลคือถ้าไม่ pin วันที่ไปติดตั้งบนเครื่องอื่นหรือติดตั้งใหม่อีกหกเดือน จะได้ library คนละเวอร์ชัน
กับที่พัฒนาไว้ แล้วโปรเจกต์พังโดยที่ไม่ได้แก้โค้ดสักบรรทัด ตอนส่งงานจบเรื่องนี้สำคัญมาก เพราะกรรมการ
อาจให้รันบนเครื่องอื่น

บรรทัด `anyio==4.9.0` มีที่มาจริงระหว่างทำ task นี้ ตอนรันเทสต์ครั้งแรกได้คำเตือน

```
DeprecationWarning: The anyio.abc.BlockingPortal alias is deprecated
```

สาเหตุคือ `anyio` เวอร์ชันล่าสุดประกาศเลิกใช้ชื่อเดิม แต่ `starlette` ที่ FastAPI ใช้อยู่ยังเรียกชื่อเดิมนั้น
ทางแก้มีสองทาง คือกดปิดคำเตือนทิ้ง หรือ pin `anyio` ให้ต่ำลงหนึ่งขั้นให้เข้ากัน เลือกทางหลังเพราะ
การปิดคำเตือนคือการซ่อนปัญหา ไม่ใช่แก้ปัญหา และคำเตือนที่ถูกปิดไว้จะกลบคำเตือนจริงที่สำคัญกว่าในอนาคต

## 3. `config.py` อ่านค่าตั้งที่เดียว

```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    database_url: str
    jwt_secret: str

    jwt_algorithm: str = "HS256"
    jwt_expire_minutes: int = 480


settings = Settings()
```

`BaseSettings` อ่านค่าจากไฟล์ `.env` และจาก environment variable ของระบบ โดยจับคู่กับชื่อฟิลด์
แบบไม่สนตัวพิมพ์เล็กใหญ่ ฟิลด์ `database_url` จึงรับค่าจาก `DATABASE_URL`

`extra="ignore"` บอกว่าถ้าใน `.env` มีตัวแปรอื่นที่คลาสนี้ไม่รู้จัก ให้ข้ามไป ไม่ต้อง error

บรรทัดสุดท้าย `settings = Settings()` สร้างอ็อบเจกต์เดียวไว้ให้ทั้งโปรเจกต์ import ไปใช้ ค่าถูกอ่าน
ครั้งเดียวตอนโหลดโมดูล ไม่ได้อ่านไฟล์ใหม่ทุกครั้งที่เรียกใช้

### ฟิลด์สองกลุ่ม บังคับกับไม่บังคับ

`database_url` กับ `jwt_secret` **ไม่มีค่าเริ่มต้น** ถ้าไม่ได้ตั้งไว้ แอปจะไม่ยอมสตาร์ตและฟ้องทันที

```
ValidationError: 2 validation errors for Settings
database_url
  Field required
jwt_secret
  Field required
```

ตั้งใจให้เป็นแบบนี้ ตอนแรกเขียนเป็น `jwt_secret: str = "change-me"` ซึ่งอันตราย เพราะวันที่ลืมสร้าง
`.env` บนเซิร์ฟเวอร์จริง ระบบจะ**ไม่ error** แต่เดินหน้าต่อโดยใช้กุญแจ `"change-me"` ที่ใครก็เดาได้
แปลว่าใครก็ปลอม token เข้าระบบเป็น admin ได้ทันที **พังตอนสตาร์ตดีกว่าพังเงียบ ๆ ตอนใช้งานจริง**

ส่วน `jwt_algorithm` กับ `jwt_expire_minutes` ยังมีค่าเริ่มต้น เพราะเป็นค่ามาตรฐานของระบบเอง
ไม่ใช่ค่าที่ต่างกันไปตามเครื่อง และไม่ใช่ความลับ ถ้าอยากเปลี่ยนก็ใส่ทับใน `.env` ได้

### แก้ค่าตั้งต้องแก้กี่ที่

| อยากทำอะไร | แก้ที่ไหน |
|---|---|
| เปลี่ยนค่า เช่นรหัสผ่านฐานข้อมูล หรืออายุ token | `.env` อย่างเดียว ค่าใน `.env` ทับค่าใน `config.py` เสมอ |
| เพิ่มค่าตั้งตัวใหม่ | ทั้งสองที่ — ประกาศฟิลด์ใน `config.py` แล้วใส่ค่าจริงใน `.env` ถ้าไม่ประกาศ ต่อให้ใส่ใน `.env` โค้ดก็อ่านไม่เห็น |
| เปลี่ยนค่าเริ่มต้น | `config.py` อย่างเดียว |

`.env.example` ไม่มีผลกับการทำงานเลย โค้ดไม่เคยอ่านมัน เป็นแค่เอกสารบอกคนที่ clone โปรเจกต์ไปว่า
ต้องตั้งค่าอะไรบ้าง เพราะ `.env` ตัวจริงไม่ขึ้น git

### ทำไมไม่เขียนรหัสผ่านลงในโค้ดตรง ๆ

สองเหตุผล หนึ่งคือรหัสผ่านจะติดไปกับ git แล้วขึ้น GitHub สองคือเครื่องแต่ละเครื่องตั้งค่าไม่เหมือนกัน
วิธีนี้แยก "โค้ด" ออกจาก "ค่าตั้งของเครื่องนี้" ได้สะอาด

`.env` ถูกใส่ใน `.gitignore` จึงไม่ขึ้น git ส่วน `.env.example` ที่ commit ไปเป็นแบบฟอร์มบอกว่า
ต้องตั้งค่าอะไรบ้าง คนที่ clone โปรเจกต์ไปก็ก๊อปเป็น `.env` แล้วเติมค่าของตัวเอง

## 4. `db.py` ทางเชื่อมฐานข้อมูล

```python
engine = create_engine(settings.database_url, pool_pre_ping=True)

SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)
```

**`engine`** คือ connection pool ทั้งแอปมีตัวเดียว การเปิด connection ไปยังฐานข้อมูลใหม่ทุกครั้ง
ที่มี request ช้ามาก pool จึงเปิดค้างไว้จำนวนหนึ่งแล้วหมุนเวียนใช้

**`SessionLocal`** คือโรงงานผลิต session ส่วน session คือพื้นที่ทำงานหนึ่งรอบ เก็บว่ารอบนี้อ่านอะไรมา
แก้อะไรไปบ้าง และยังไม่ได้บันทึกอะไร ทุก request จะได้ session ของตัวเองหนึ่งตัว

### สามพารามิเตอร์ที่ต้องอธิบายได้

**`pool_pre_ping=True`** ก่อนหยิบ connection จาก pool มาใช้ ให้ยิงคำสั่งเล็ก ๆ ทดสอบก่อนว่ายังมีชีวิต
ถ้าตายแล้วให้ทิ้งแล้วเปิดใหม่ ไม่งั้นเวลา PostgreSQL รีสตาร์ต หรือ connection ถูกตัดเพราะไม่ได้ใช้นาน
request แรกหลังจากนั้นจะพังโดยหาสาเหตุไม่เจอ

**`autoflush=False`** ปกติ SQLAlchemy จะแอบส่งข้อมูลที่ค้างอยู่ลงฐานข้อมูลให้อัตโนมัติก่อนทุก query
ปิดไว้เพราะเราต้องการคุมเองว่าจะเขียนตอนไหน ซึ่งจำเป็นมากในเฟส 3-5 ที่การตัดสต็อกแบบ FIFO
และการจองเลขที่บิลต้องเกิดตามลำดับที่กำหนดภายในทรานแซกชันเดียว

**`expire_on_commit=False`** ค่าเริ่มต้นของ SQLAlchemy คือ `True` ซึ่งหลัง `commit()` จะทำให้อ็อบเจกต์
ทุกตัว "หมดอายุ" พออ่านฟิลด์ไหนก็ยิง query ใหม่ไปถามฐานข้อมูล ปัญหาคือถ้าตอนนั้น session ปิดไปแล้ว
จะ error ทันที ในงานนี้ทุก endpoint ที่บันทึกข้อมูลต้องส่งข้อมูลนั้นกลับไปให้ frontend จึงปิดไว้

## 5. `main.py` ประกอบแอป

```python
app = FastAPI(title="ระบบจัดการอู่ซ่อมรถ", version="0.1.0")

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)


@app.get("/api/health")
def health():
    return {"status": "ok"}
```

**CORS คืออะไรและทำไมต้องมี** frontend รันที่พอร์ต 5173 ส่วน backend รันที่ 8000 เบราว์เซอร์ถือว่า
คนละพอร์ตคือคนละต้นทาง และมีกฎความปลอดภัยว่าห้ามเว็บหนึ่งเรียก API ของอีกที่หนึ่งโดยพลการ
ถ้าฝั่ง server ไม่ประกาศอนุญาต React จะเรียก API ไม่ได้เลยและขึ้น error ใน console

`allow_origins` จึงระบุว่าอนุญาตเฉพาะ `http://localhost:5173` ตอนขึ้นใช้งานจริงต้องเปลี่ยนเป็น
โดเมนจริงของระบบ **ห้ามใส่ `*`** เพราะเท่ากับอนุญาตให้เว็บใดก็ได้ในโลกยิง API เข้ามา

**`/api/health`** เป็น endpoint สั้นที่สุดที่พิสูจน์ว่าแอปประกอบสำเร็จและตอบ request ได้ ในระบบจริง
มันมีประโยชน์เป็นจุดให้ระบบ monitoring คอยเช็คว่าเซิร์ฟเวอร์ยังมีชีวิตอยู่

## 6. เทสต์ตัวแรกและลำดับ TDD

```python
def test_health_returns_ok():
    client = TestClient(app)
    response = client.get("/api/health")
    assert response.status_code == 200
    assert response.json() == {"status": "ok"}
```

`TestClient` ยิง request เข้าแอปตรง ๆ ในหน่วยความจำ ไม่ต้องเปิด uvicorn จริง เทสต์จึงเร็วมาก
และไม่ชนพอร์ตกับอะไร

### ลำดับที่ทำจริงใน task นี้

1. เขียนเทสต์ก่อน ทั้งที่ยังไม่มีไฟล์ `app/main.py`
2. รันแล้วได้ `ModuleNotFoundError: No module named 'app.main'` — นี่คือขั้น **RED**
3. เขียน `config.py` `db.py` `main.py`
4. รันอีกครั้งได้ `1 passed` — นี่คือขั้น **GREEN**

**ทำไมต้องรันให้เห็นว่าไม่ผ่านก่อน** เพื่อพิสูจน์ว่าเทสต์จับของจริง ถ้าเขียนโค้ดก่อนแล้วเทสต์ผ่านตั้งแต่
ครั้งแรก จะไม่มีทางรู้ว่าเทสต์นั้นตรวจอะไรจริงหรือเปล่า เทสต์ที่ผ่านตลอดไม่ว่าโค้ดจะเป็นยังไง
คือเทสต์ที่ไม่มีประโยชน์

## 7. ฐานข้อมูลสองตัว

```sql
create user garage with password 'garage';
create database garage owner garage;
create database garage_test owner garage;
```

`garage` คือฐานข้อมูลจริง `garage_test` ใช้ตอนรันเทสต์เท่านั้น

**ทำไมต้องแยก** เพราะโครงเทสต์ที่จะสร้างใน Task 2 จะสั่ง `drop schema public cascade` ทิ้งทั้งหมด
แล้วสร้างใหม่ทุกครั้งที่เริ่มรันเทสต์ ถ้าชี้ไปฐานเดียวกับของจริง ข้อมูลลูกค้าและบิลจะหายทุกครั้งที่รันเทสต์

ระบบไม่ได้เชื่อมต่อด้วยผู้ใช้ `postgres` ซึ่งเป็น superuser แต่สร้าง user ชื่อ `garage` ขึ้นมาใหม่
และให้เป็นเจ้าของสองฐานนี้เท่านั้น หลักคือให้สิทธิ์เท่าที่จำเป็น ถ้าแอปถูกเจาะ ผู้บุกรุกก็ยุ่งกับ
ฐานข้อมูลอื่นบนเซิร์ฟเวอร์เดียวกันไม่ได้

| ทำไม `jwt_secret` ไม่มีค่าเริ่มต้น | ถ้ามีค่าเริ่มต้น วันที่ลืมสร้าง `.env` ระบบจะเดินหน้าต่อด้วยกุญแจที่ใครก็เดาได้ แล้วปลอม token เข้าเป็น admin ได้ ให้พังตอนสตาร์ตดีกว่าพังเงียบตอนใช้งาน |
| แก้ค่าตั้งต้องแก้ทั้ง `.env` และ `config.py` ไหม | เปลี่ยนค่าเดิม แก้ `.env` อย่างเดียว เพิ่มค่าตัวใหม่ต้องแก้ทั้งสองที่ เพราะ `config.py` คือการประกาศว่ามีค่านี้อยู่ ส่วน `.env` คือค่าจริงของเครื่อง |
| `expire_on_commit=False` ทำอะไร | ทำให้อ่านค่าจากอ็อบเจกต์ได้หลัง commit โดยไม่ยิง query ใหม่ จำเป็นเพราะทุก endpoint ที่บันทึกข้อมูลต้องส่งข้อมูลนั้นกลับไปให้ frontend |
